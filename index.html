System One 决策模型 typesafe/jev-1.13

输入「状态 + 类型化问题」，输出「带概率的结构化决策」

Jev 不生成文本。你给它一个 state（工单、订单、任意 JSON）和一组问题（Noul 是否判断 / Choice 多选分类 / Score 量表打分）， 它在一次请求里并行回答全部问题，每个答案都带校准过的概率——软件据此决定「自动执行」还是「转人工」。输入 $0.042 / 百万 token，输出免费，典型延迟 70–500ms。

~0.1s单次决策延迟
$0.000081单次决策成本
193× / 444×对比 LLM 快 / 便宜
32K上下文窗口

① 场景预设 一键填充 state + questions

② State（被评估的数据）JSON 对象或纯文本

state 可以是纯文本，也可以是嵌套 JSON——把工单、订单、政策一起放进去，Jev 会综合判断。

③ Questions（类型化问题）同一 state 并行评估，加问题几乎不增加延迟

置信度阈值 0.70

④ 决策结果 概率 ≥ 阈值 → 自动执行；否则 → 转人工

为什么不是直接问 LLM？

      

        LLM（系统二）逐 token 生成文本，应用层还要解析、校验、重试；Jev（系统一）一次并行输出带概率的结构，没有自由文本可以跑偏。
        两者互补：LLM 负责开放推理，Jev 负责流程里高频的路由 / 分级 / 评分 / 守门判断——例如 LangChain 的 Auto Mode 会在高危工具执行前用 Jev 做风险评估。
